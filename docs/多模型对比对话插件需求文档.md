# 多模型对比对话插件 —— 需求文档

> 版本：v0.2（第二轮交互增强已完成）
> 日期：2026-09-11
> 状态：✅ 已实现并本地安装（`npm run install:local`）

---

## 1. 一句话概述

一个 VS Code 插件：在独立的编辑器标签页里，把一个问题**同时**发给多个已配置的大模型，**并排对比**它们的流式回答，支持多轮追问、图片输入，并把对话历史自动保存在本地。

## 2. 目标用户

- **个人开发者 / 研究者 / AI 爱好者**，主要单人、单机使用。
- 已在本机配置好多个模型端点（当前为 Airouting 的 GPT 模型 + DeepSeek），希望**横向对比不同模型的回答质量、风格与速度**。
- 对 VS Code 有基本使用经验，但不要求会编程。

## 3. 核心使用场景

1. **同题对比**：同一个问题同时发给 4 个模型，并排查看谁答得更好、更快。
2. **多轮压力测试**：连续追问，对比各模型在多轮上下文下的表现与稳定性。
3. **多模态对比**：发一张图片，对比支持视觉的模型之间的解读差异。

## 4. 核心功能点（清单）

### F1. 聊天界面（独立标签页）

- FR-01 通过命令（命令面板）打开一个**独立编辑器标签页**作为聊天界面，占用大面板空间。
- FR-02 提供**模型选择区**，列出全部 4 个模型；**默认全选**，可单独取消勾选。
- FR-03 提供**输入框 + 发送按钮**：回车发送，Shift+回车换行。
- FR-04 支持**粘贴 / 拖入图片**，作为消息附件随文本一起发送。

### F2. 并发提问 + 并排对比

- FR-05 发送时，把当前消息**同时**（并发）发送给所有已勾选的模型。
- FR-06 每个模型渲染为一张独立的**答案卡片**，并排布局（响应式，窗口变窄时自动换行/堆叠）。
- FR-07 每张卡片显示：模型名、状态（等待中 / 生成中 / 完成 / 失败 / 已取消）、本次耗时。
- FR-08 各模型**独立流式输出**（打字机效果），互不阻塞，谁先生成就先显示。

### F3. 多轮对话

- FR-09 每个模型**独立维护自己的对话历史**（上下文），互不串扰。
- FR-10 追问时，每个模型只携带**自己的历史**（含图片消息）。
- FR-11 支持**新建会话 / 清空当前会话**。

### F4. 历史保存与恢复

- FR-12 每次会话**自动保存到本地**。
- FR-13 提供**历史会话列表**，可点开恢复某次历史会话。
- FR-14 恢复后允许**继续追问**（见「待确认项」）。

### F5. 安全与配置

- FR-15 模型**密钥交由 VS Code 的密钥存储（SecretStorage）管理**，插件代码内**绝不硬编码 API Key**。
- FR-16 模型列表**复用 VS Code 的模型接口（Language Model API）**读取本机已配置的端点与模型，不自行解析 `chatLanguageModels.json`。

## 6. 非功能需求

- **NFR-01 容错**：单个模型请求失败 / 超时 / 被取消，不影响其它模型的正常显示，并在该卡片上给出错误提示。
- **NFR-02 可取消**：提供"停止"能力，可中断所有正在进行的请求。
- **NFR-03 性能**：流式渲染不卡顿，长回答可滚动查看。
- **NFR-04 安全**：密钥不进源码仓库、不写入日志。

## 7. 这一版明确「不做」（范围外）

- ❌ 编辑器代码上下文（选中代码作为输入）。
- ❌ 工具调用（tool calling），尽管配置中标了 `toolCalling: true`。
- ❌ 插件自行直连各厂商 HTTP API（统一走 VS Code 模型接口）。
- ❌ Copilot 订阅原生的模型（本版只做上述 4 个自定义端点）。
- ❌ 模型参数调参界面（temperature 等）。
- ❌ 多账号 / 多人协作 / 云同步。
- ❌ 其它模型来源（Ollama 本地模型等）。
- ❌ 发布到 Marketplace（本版仅本地使用 / `.vsix` 分发）。

## 9. 技术要点（简要，供开发参考）

- 语言：TypeScript；脚手架：`yo code` / `generator-code`。
- 界面：Webview（HTML/CSS/JS），独立编辑器标签页。
- 模型调用：VS Code `vscode.lm` API（`selectChatModels` + `sendRequest`，流式 `response.text`）。
- 并发：`Promise.all` 同时向所有勾选模型发请求。
- 密钥：`context.secrets`（SecretStorage）。
- 历史：本地文件读写 + 会话列表 UI。

### 10.2 TBD-03 的实现方式与文档不符（重要）

文档原写的是"**自动跳过**图片"。实现时发现：`vscode.lm` 在**消费模型**这一侧
**没有暴露稳定的模型能力查询接口**（`LanguageModelChatCapabilities` 只存在于
"提供模型"的那一侧），所以无法提前得知某个模型是否支持图片。

实际行为改为两段式降级：

1. 若能读到能力信息且明确为 `false` → 直接跳过图片，不浪费一次失败请求；
2. 若读不到 → **带图请求一次**，失败后**自动去掉图片重试**，成功则在该卡片上
   标注"该模型不支持图片，本次已仅发送文本"。

**效果与文档意图一致，但代价是多一次失败请求。**

### 10.3 新增的决策：默认勾选与显示范围（原文档未覆盖）

原需求是"列出全部 4 个模型，默认全选"。但 `vscode.lm.selectChatModels({})` 会返回
**所有**可用模型 —— 在启用 Copilot 的环境里通常有十几个（还可能有重名的，例如
`customendpoint` 与 `copilot` 下都叫 `GPT-4o mini`）。若无条件全部列出并默认全选，
一次提问会并发打到十几个模型上：费用高、易触发限流、对比视图也没法看。

因此新增三个设置项（前两个可在界面上通过「只看我的模型」开关切换）：

| 设置 | 默认值 | 作用 |
|------|--------|------|
| `multiModelCompare.preferredVendors` | `["customendpoint"]` | 定义「我的模型」的范围（正好是第 5 节那 4 个） |
| `multiModelCompare.onlyPreferredVendors` | `true` | 只**显示**上述 vendor 下的模型；关闭后显示全部 |
| `multiModelCompare.maxSelectedModels` | `8` | 默认勾选的数量上限，`0` 表示不限制 |

两条关键约束：

1. **显示范围与可选范围严格一致**：`this.models` 与界面所见保持一致，
   避免"界面看不到但请求实际发了"这种不一致。
2. **隐藏即不可选**：勾选列表里属于隐藏范围的模型会被移除，不会残留。

被隐藏了多少个模型会在界面上明确提示，不会静默改变行为。

### 10.4 其它实现细节上的取舍

- **图片放大**：webview 里 `window.open(dataURL)` 会被拦截，改为内置遮罩层
  （点击放大、再点或按 `Esc` 关闭）。
- **Markdown 渲染**：极简实现（围栏代码块 / 行内代码 / 粗体 / 标题），
  先做 HTML 转义以防 XSS；超过 20000 字符的回答退化为纯文本渲染，避免重排卡顿。
- **密钥**：扩展内不出现任何 API Key，一律复用 VS Code 已配置的模型。
- **测试**：`npm test` 运行 `scripts/smoke-render.mjs`，校验渲染器的转义与围栏解析。
- **安装方式**：`npm run install:local` 直接把构建产物复制到
  `~/.vscode/extensions/local.multi-model-compare-<version>/`，无需打包、无需下载；
  `npm run uninstall:local` 卸载。重启 VS Code 后在任何窗口都可用。

### 11.1 需求与实现对照

| # | 需求 | 实现方式 |
|---|------|----------|
| 1 | 历史列表挪到右侧 | HTML 顺序调整为「消息区在前、历史在后」，CSS 边框由 `border-right` 改为 `border-left` |
| 2 | Markdown 正常渲染 | 新写 `media/markdown.js`（零依赖），替换原先只认 4 种语法的内联渲染器 |
| 3 | 显示结果开关 | 新增「显示结果」行（**独立于**「参与对比」），默认全勾 |
| 4 | 模型名右侧复制按钮 | 卡片标题栏加「复制」，复制 **Markdown 原文**，带「已复制」反馈 |
| 5 | 卡片宽度可拖拽 | 布局由 Grid 改 Flex，卡片右边缘加拖拽手柄，宽度全局持久化 |

### 11.2 需求 3 的语义确认（方案 A）

需求原文「通过『参与对比』上方勾选来控制是否展示结果」有三种可能解释，经确认采用**方案 A**：

> **独立的显示开关**：只控制已生成结果的**显隐**，**不影响**请求发给哪些模型。
> 即"我问了 4 个，但只想看其中 2 个的答案"。

两条约束：

1. **默认全勾**（显示全部结果），只有用户主动取消才隐藏；
2. **隐藏不清数据** —— 回答仍在会话文件里，重新勾上立即恢复，不会重新请求、不额外计费。

界面上还提供「全部显示（N 项已隐藏）」按钮一键恢复，避免用户忘了自己隐藏了什么。

### 11.3 需求 2：Markdown 的深度取舍

对比两条路线后选择**手写增强**，理由是项目为零构建（`tsc` + 直接复制 `media/`），
引入 `markdown-it` 会连带引入打包步骤并影响 `install:local` 脚本。

| 支持 | 不支持 |
|------|--------|
| 标题、粗体、斜体、删除线、行内代码、围栏代码块 | 语法高亮（需额外库，且体积大） |
| 有序 / 无序列表（含嵌套）、表格、引用块、分隔线、链接 | HTML 内嵌（安全性考虑，一律转义） |
| 段落内换行（转 `<br>`） | 数学公式、脚注、任务列表等扩展语法 |

安全上保持**先转义再拼标签**，并额外做了两件事：

1. **行内代码先抽成占位符**，否则 `` `**x**` `` 里的 `*` 会被误当强调符号；
2. **链接协议白名单** —— 只放行 `http/https/mailto/#/相对路径`，`javascript:` 与 `data:` 一律拒绝。

原「超过 20000 字符退化为纯文本」的保护保留。

### 11.4 需求 5：拖拽的风险评估结论

**评估结论：风险可控，予以实现。** 唯一明显代价是放弃「窗口变窄自动堆叠」——
这是自由调宽度的必然取舍，改为横向排列 + 横向滚动（滚动条用 webkit 伪元素强制常驻，
否则 macOS 的 overlay 滚动条会让用户不知道可以横向滚动）。

按用户要求**只调宽度、不调高度**，实现细节：

- 手柄位于卡片右边缘（`cursor: col-resize`），宽度夹在 160–1600px；
- 拖拽时同步更新**所有同一模型的卡片**（多轮会话里每个模型每轮都有一张卡）；
- 松手后写入 `settings.json`，**全局记住**（跨轮次、跨会话、重启后仍生效）；
- **双击手柄**恢复该卡片默认宽度（340px），作为拖坏后的兜底；
- 重置尺寸不影响「隐藏即不可选」等其它状态。

### 11.5 本轮新增的存储与消息

存储新增 `settings.json`（与具体会话无关，全局生效）：

```json
{ "cardWidths": { "customendpoint:gpt-5.6-sol": 500 } }
```

Webview 与扩展之间新增两条消息：

| 方向 | 消息 | 作用 |
|------|------|------|
| 界面 → 扩展 | `saveWidths` | 拖拽结束后保存宽度（扩展侧会夹取到 160–1600，并过滤非数字） |
| 界面 → 扩展 | `openLink` | 用系统浏览器打开回答里的链接（webview 自己开不了，且限制了只放行 http/https/mailto） |

`session` 消息新增 `cardWidths` 字段，用于恢复宽度。

### 11.6 本轮修复的问题

| 问题 | 原因 | 修复 |
|------|------|------|
| 代码块撑破卡片宽度 | flex 子项的 `min-width: auto` 允许内容溢出 | `.card-body` 加 `min-width: 0` + `overflow-x: hidden` |
| 语言标签悬在代码块外面 | 标签渲染在 `<pre>` 之前 | 移入 `<pre>` 内绝对定位，并给 `has-lang` 让出 `padding-top` |
| 横向滚动条看不见 | macOS overlay 滚动条 + `scrollbar-width: thin` 覆盖了自定义样式 | 只保留 webkit 伪元素（同时写标准属性会让自定义失效） |
