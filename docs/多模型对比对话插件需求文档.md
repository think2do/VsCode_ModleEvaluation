## 0. 本文档怎么用

**重建顺序**（不要跳步）：

```
存储层 → 模型发现 → 单模型流式请求 → 面板与消息协议 → Webview 骨架与渲染
      → 交互细节（编辑提问 / 导入 / 图片 / 历史 / 并排对比）
```

先打通「一问一答」再补边缘功能。**不要**一上来就做并排对比与编辑提问 —— 它们依赖前面所有层都正确。

**阅读优先级**：

| 顺序 | 章节 | 为什么 |
|---|---|---|
| 1 | §1 产品定义（**尤其 §1.5 术语表**） | 几个概念极易混淆，搞错会导致整个交互做反 |
| 2 | §2 功能规格 | 每条给出规则 + 边界情况 + 验收点 |
| 3 | §3 界面契约 / §4 消息协议 | **硬契约**。不按它做，前后端一定对不上，且症状是「点了没反应」这类静默失效 |
| 4 | §5 数据模型 / §6 构建约束 | 存储格式需与现有会话文件兼容；构建约束违反会导致项目根本跑不起来 |
| 5 | §7 架构 / §8 设计决策 | 决定你写出的是可维护代码，还是又一个千行 God Object |
| 6 | §10 验收 | 用来自检 |

## 1. 产品定义

### 1.1 一句话

一个 VS Code 扩展：在独立面板里把**同一个问题同时发给多个大模型**，流式对比它们的回答，
支持多轮追问、图片输入、本地历史。

### 1.2 目标用户

- 个人开发者 / 研究者 / AI 爱好者，**单人单机**使用；
- 已在本机配好多个模型端点（Copilot 订阅，或自己在 `chatLanguageModels.json` 里添加的自定义端点）；
- 会基本使用命令面板，**不要求会编程**。

### 1.3 核心使用场景

| # | 场景 | 说明 |
|---|------|------|
| 1 | **同题对比** | 同一个问题同时发给多个模型，并排看谁答得更好、更快 |
| 2 | **多轮压力测试** | 连续追问，对比各模型在多轮上下文下的表现与稳定性 |
| 3 | **多模态对比** | 发同一张图，对比各模型对图片的解读差异 |

### 1.4 与「多开几个 Copilot 窗口」的区别

核心差异是**上下文隔离**：每个模型只回放**自己答完的**历史轮次。

| | 共享一份历史（常见做法） | 本项目 |
|---|---|---|
| A 答完第 1 轮，B 第 1 轮失败 | 第 2 轮把 A 的回答也发给 B，B 要理解「别人的话」，容易跑偏 | B 的第 2 轮只带第 2 轮的提问，不带 A 的回答 |
| 某模型中途失败 / 被取消 | 污染所有模型的后续上下文 | 只影响它自己，其它模型无感 |
| 对比结论的可比性 | 差（各模型看到的历史不同） | 好（每个模型都独立走完全程） |

「共享上下文」是这个设计的**手动例外**：用户可把某一条回答设为公共参考（见 §2.5）。

### 1.5 术语表

**重建时最容易搞错的就是这几个词。**

| 术语 | 含义 | 不是什么 |
|---|---|---|
| **模型 key** | 模型的稳定标识，形如 `vendor:id`（如 `customendpoint:gpt-5.6-sol`）。所有会话数据、勾选状态都以它为准 | 不是显示用的模型名（名字可能重复） |
| **轮次（turn）** | 一次「提问 + 各模型各自的回答」的集合 | 不是「一个模型的一次回答」 |
| **参与提问** | 该模型是否参与**新问题**的发送。由悬浮条卡片**右侧开关**控制 | 不影响能否看它已有的回答 |
| **并排对比** | 一种**展示**方式：某一轮同时显示被勾选的几个模型，横向排开。由**左侧复选框**控制 | 不等于「参与提问」，它只影响怎么看 |
| **单读聚焦** | 另一种展示方式：某一轮只显示一个模型的回答 | 与并排对比**互斥**（进单读会清掉该轮的并排勾选） |
| **展示设置** | 每轮各自持有的「单读看谁 / 并排哪几个」，存在该轮的 `view` 里 | **不是**全局状态（见 §8.2） |
| **上下文隔离** | 默认行为：每个模型只回放自己答完的轮次 | 与「共享上下文」是两回事 |
| **共享上下文** | 手动把**某一条回答**设为公共参考，之后**每个模型**提问都带上它 | 不是「所有模型共享全部历史」 |
| **降级（图片）** | 模型不支持图片时，去掉图片只发文字重试 | 不是「拒发」或「报错终止」 |
| **wire / `Wire*`** | 类型前缀，表示「要发给 Webview 的结构」。与落盘结构只差图片：wire 版带 `dataUrl` 供界面直接渲染 | 不是另一份数据源 |

## 2. 功能规格

每条格式：**规则** → **边界情况** → **验收点**。

### 2.1 界面与布局

**规则**

单个 Webview 面板（独立编辑器标签页），自上而下四个区块 + 一个侧栏：

| 区块 | 位置 | 内容 |
|---|---|---|
| 工具栏 | 顶部固定 | 应用名、会话标题、`新建会话`、`历史` |
| **悬浮控制条** | 消息区**顶部悬浮**（`position: absolute`） | 每个可用模型一张迷你卡（见 §2.2） |
| 消息区 | 中部可滚动 | 一轮一条：轮次头 → 提问区 → 选项卡 → 回答卡片 |
| 输入区 | 底部固定 | 附件缩略图 + 文本框 + `发送` / `停止` |
| 历史侧栏 | 右侧 | 历史会话列表（可整栏隐藏） |

- 悬浮条**半透明 + 毛玻璃**（`backdrop-filter: blur`），内容从它下面滚过去；
- 悬浮条出现时消息区顶部自动多留出等高内边距，不遮住第一轮；
- 单读模式正文最大宽度 `--read-width`（880px）并居中；
- 输入框与「发送」/「停止」**等高**（`--composer-h`，34px）。

每轮 DOM 结构（顺序固定）：

```
.turn
├── .q-head            第 N 轮 · 时间
├── .q-row             提问区（.q-bar 标签+编辑按钮 / .q-text / .thumbs / .q-edit-area）
├── .tabbar            本轮模型选项卡（单读时可见；并排时仍显示，点它可退出并排）
├── .answers-label     「模型回答」小标题（仅单读时可见）
└── .cards             回答卡片容器（.cards.tile = 并排）
```

**边界情况**：没有任何可用模型时悬浮条隐藏，不占位。

**验收点**：窗口拉宽 / 拉窄，阅读栏居中不变形；悬浮条始终不遮住第一轮内容。

### 2.2 模型发现与选择

**规则**

1. 用 `vscode.lm.selectChatModels({})` 拿到**本机全部**可用模型 ——
   **不解析** `chatLanguageModels.json`，**不接触任何密钥**（见 §8.9）；
2. 按设置筛出**可见**模型（三个设置见 §5.4）；
3. 把勾选状态**收敛**到可见模型上（见下）；
4. 下发 `models` 消息 + 一句可选警告。

**白名单与回退**

- `preferredVendors`（默认 `["customendpoint"]`）定义「我自己添加的模型」；
- `onlyPreferredVendors`（默认 `true`）为真时**只显示**白名单内的；
- ⚠️ **白名单一个都没匹配上时，退回显示全部并明确提示**，绝不给出空白列表 ——
  用户看不到模型时没法自己排查。提示须写明是哪个设置导致的。

**勾选收敛规则**（按顺序执行）

1. 已勾选且仍可见的 → 保留（尊重用户选择）；
2. 一个都没勾上（首次使用，或原先勾的都被隐藏了）→ 默认**全选**；
3. 超过 `maxSelectedModels`（默认 8，`0` = 不限制）→ 只勾前 N 个**并明确告知**被截断；
4. 不可见的模型从勾选列表里**移除**（「隐藏即不可选」，防止「看不见但仍偷偷参与对比」）。

**迷你卡的三段结构**（三段职责独立，**不要合并**）

| 位置 | 控件 | 管什么 | 行为 |
|---|---|---|---|
| 左 | 复选框 | 怎么看 | 加入**并排对比**（作用于最新一轮）；空会话时置灰 |
| 中 | 模型名（可点） | 看谁 | **单读**该模型（作用于最新一轮） |
| 右 | 开关 | 问不问 | 是否参与提问；变更立即回报 `selectModels` 并写入会话 |

- 模型名**完整显示不截断**：卡片宽度跟着名字走（`min-width: max-content`），一行放不下时横向滚动；
- 不同 vendor 下有同名模型时，显示名补上 vendor（`名字 · vendor`）；
- 明确不支持图片的模型，名字旁加「无图」小徽标。

**边界情况**：`selectChatModels` 抛错时把错误文案并入警告一起下发，不静默失败。

**验收点**：把 `preferredVendors` 改成一个不存在的值时，界面**不是空的**，
而是显示全部模型 + 一条说明原因与设置名的提示。

### 2.3 提问与并发流式

**规则**

- 输入 = 文本（可空）+ 图片（0–4 张）。**两者都空则不发送**；
- 未勾选任何模型 → 不发送，提示「请至少勾选一个模型。」；
- 发送后**立即**清空输入区与附件，进入「发送中」（禁用发送、启用停止、收起编辑态）。

服务端按下面顺序处理：

1. **图片落盘**（失败只提示，不中断本次发送）；
2. 建立本轮结构：`turn.responses[key] = { text: '', status: 'pending' }`，只为**本轮要问的模型**建条目；
3. 推 `turn` 消息（界面立即画出全部 pending 卡片）；
4. 落盘会话 + 广播历史列表；
5. **并发**对全部目标模型发起请求（`Promise.all`），每个模型独立：
   - 各自的 `CancellationTokenSource`（以模型 key 为索引，供「停止」统一取消）；
   - 状态置 `streaming`；
   - `model.sendRequest(messages, {}, token)`，`for await (const chunk of response.text)`
     流式累积并推 `chunk`；
   - 收尾三选一：`done`（含 `elapsedMs`）/ `cancelled`（**保留已收到的文本**）/
     `error`（含中文文案）；
6. 全部结束后落盘 + 广播历史 + 推 `idle`（界面解除「发送中」）。

**会话标题**：首轮提问时取提问前 40 字；纯图片消息用 `(图片消息)`。

**边界情况**

- 单个模型失败 / 取消**不能**影响其它模型（各自独立的 try/catch 与令牌）；
- 取消时要 `break` 出流循环，不能继续累积；
- `sendRequest` 抛错后要用**同一份** response 对象继续累积（重试路径见 §2.6）。

**验收点**：断网或给一个不存在的模型发请求时，其它模型的回答**照常完成**，
失败的那张卡片显示中文错误建议。

### 2.4 两种展示方式（按轮）

**这是本项目最容易做错的地方。**

**规则**

- 展示状态**按轮**存：`turn.view = { focusKey?, compareKeys? }`；
- **默认单读**（`focusKey`，不设置时取本轮第一个问过的模型）；
- **并排**：该轮 `compareKeys` 非空时，同时显示被勾选的那几个，横向排开；
- **两者互斥**：进入单读会清掉该轮的并排勾选（否则「点了卡片什么都没变」）；
- **作用域**：
  - 悬浮条（复选项 / 卡片正文）作用于**最新一轮** —— 它是「现在」的快捷控制条；
  - 每轮**选项卡**与卡片标题栏上的**模型名**作用于**它自己那一轮**；
- 改动通过 `updateTurnView` 写回会话（切换会话后看法还在）；
- 新的一轮**继承上一轮**的看法（上一轮在并排，新的一轮也并排）。

**并排布局**

- 容器 `.cards.tile`：`display: flex`、横向滚动；
- 每格 `.card`：`flex: 1 1 260px; min-width: 260px`
  （**必须覆盖**基础规则的 `min-width: 0`，否则会被压扁），
  格内正文 `max-height: 60vh` 纵向滚动；
- 各格**等高**，便于逐条对照；
- 解除 `--read-width` 限制（铺满可用宽度）；
- **隐藏** `.answers-label`（每格自带标题栏，重复）；
- **保留** `.tabbar` —— 点它能退出并排，**不要顺手隐藏它**；
- 某模型本轮未参与 → 插一个 `.card.tile-missing` 虚线占位（顺序按模型列表），
  保证各轮列出的列一致。

**单读模式**：该轮未问过当前聚焦模型时，显示 `本轮未向该模型提问。` 占位，
**不要**默默换成别的模型 —— 让「正在读谁」始终明确。

**边界情况**

- 重排要**保持滚动位置**：先抓一个锚点轮次与它的相对偏移，重排后还原
  （否则切换聚焦 / 进出并排时视口会莫名其妙跳走）；
- 刷新可见性的函数必须同步**所有**派生 UI，漏一处就会出现「要点两下才有反应」：

  | 要同步的东西 |
  |---|
  | `.cards` / `.turn` 的 `.tile` 类 |
  | 每张 `.card` 的 `.hidden` / `.tile` |
  | `.tab` 的 `.on` 类 **和** `.tab-check` 的 `checked` |
  | `.tile-missing` 占位格的增删 |
  | `.pane-missing` 的显隐 |
  | 悬浮条上的 active / off / comparing / checked / disabled |

**验收点**：① 勾悬浮条复选框 → **真的**进入并排布局（不只是打个钩）；
② 点悬浮条卡片正文 → **真的**切换显示的模型；③ 点某轮的卡片名 → 只影响那一轮。

### 2.5 多轮与上下文

**默认：上下文隔离**

构造某模型的请求时，只回放该模型**自己**满足以下条件的轮次：

- `responses[key].status === 'done'` **且** 文本非空
  （失败 / 取消 / 空的直接跳过，否则会把半截内容当成「它说过的话」发过去）；
- 该轮图片：**仅在**该模型支持图片、且它此前没有因不支持图片而丢过附件时才发
  （`droppedImages`，避免每轮都白失败一次）。

每条历史轮次还原成 `User(prompt + 图片)` + `Assistant(text)` 一对。

**手动例外：共享上下文**

- 用户可把某条回答「设为上下文」（`session.contextSource = { turnId, modelKey }`）；
- 之后**每一轮**请求都会在历史之后、当前提问之前插入一条
  `Assistant("【被选中的模型回答】\n" + 该回答全文)`；
- 只有 `done` 且文本非空的回答能设；生成中 / 失败的不能；
- 顶部会话标题旁出现 `上下文：模型名 · 第 N 轮 ×` 徽标，**点击即清除**；
- 该条回答的按钮文案变为「当前上下文」；
- 若那一轮的**提问被编辑**（回答即将改变）→ 上下文**自动解除**。

**边界情况**

- 上下文指向的轮次 / 回答已不存在 → 静默跳过，不报错；
- 共享上下文与隔离**同时生效**：各自的对话历史照旧隔离，额外多一条公共参考
  （重建时不要为了「共享上下文」把隔离关掉）。

**验收点**：让 A 在第 1 轮失败、B 答完第 1 轮，然后问第 2 轮 ——
B 的请求里**不能**包含 A 的回答；而设了共享上下文后，A、B 的请求里**都要**包含它。

### 2.6 图片输入与能力降级

**规则**

- 支持**粘贴**（`Cmd/Ctrl+V`）与**拖入**输入区；
- 上限：单张 ≤ 20MB、单条消息 ≤ 4 张（超出给提示并跳过 / 停止添加）；
- 非图片类型的文件直接忽略；
- 发送时图片落盘到 `images/<uuid>.<ext>`，会话文件里**只存文件名**（不存 base64，避免膨胀）；
- 界面渲染用 data URL（扩展侧读盘后 base64 化，带缓存，同一张图不重复读盘）。

**能力探测与两段式降级**

`vscode.lm` 的**消费侧没有**暴露稳定的能力查询接口
（`LanguageModelChatCapabilities` 只存在于「提供模型」那一侧），因此支持情况有三种结果：

| 探测结果 | 行为 |
|---|---|
| `false`（明确不支持） | **直接不发图**，标记 `droppedImages`，不浪费一次失败请求 |
| `undefined`（无法判断） | **带图试一次**；失败且**非用户取消** → 清空重试（去掉图片）一次；成功则标记 `droppedImages` |
| `true` | 正常带图发送 |

- 重试**仅一次**，且只在「上次带了图」时进行；
- 用户取消（`CancellationError` 或令牌已取消）**不触发**重试，直接结束为 `cancelled`；
- 标记 `droppedImages` 后，界面上该卡片下方显示
  「该模型不支持图片，本次已仅发送文本。」，并且该模型的历史轮次也不再发图。

**其它**

- **纯图片消息也要带一个非空文本部分**（部分端点不接受空文本）；
- 图片丢了（文件不存在）→ 跳过这张图，不让整个请求失败；
- 点缩略图放大（webview 里 `window.open` 会被拦截，需自绘遮罩层；再点或 `Esc` 关闭）。

**验收点**：给明确不支持图片的模型发图 → 卡片出现降级说明且**没有**多余的失败请求；
给能力未知的模型发图 → 最多出现一次失败重试。

### 2.7 编辑提问（仅最新一轮）

**规则**

- 入口：提问区右上角的「编辑」按钮（低对比度**常驻可点**，
  不要用 hover 隐藏 + `pointer-events:none`，那样点不到）；
- **只允许编辑最新一轮**（理由见 §8.4）；
- **生成中禁止**编辑（按钮置灰，提示先停止或等完成）。

三个出口：

| 按钮 | 行为 |
|---|---|
| **仅保存** | 只改文字，不动已拿到的回答 |
| **保存并重新生成** | 用新提问重新问**本轮原有的那几个模型**（以该轮 `responses` 里已有的 key 为准，不受之后开关变化影响），清空重出 |
| **取消** / `Esc` | 放弃修改 |

- `Cmd/Ctrl + Enter` = 保存并重新生成；
- 同一时刻只允许一处编辑（开启新的会先取消旧的）。

**副作用**（都要实现）

- 内容**没变就不写盘**（避免空点「保存」也刷新时间）；
- 改的是**第一轮** → 同步更新会话标题；
- 该轮是**共享上下文来源** → 自动解除；
- 回推用**轻量**消息（`prompt`），只刷新那一轮的提问区，**不整屏重渲染**
  （整屏重渲染会丢掉并排对比状态）；
- 该消息里的 `contextSource` 必须是 `null` 而不是 `undefined`（见 §4.3）；
- 带图片的轮次只改文字，图片原样保留；
- 改过的提问显示一个「已编辑」小标记。

**边界情况**：编辑期间**不能重建卡片**（否则 textarea 会被顶掉）——
所以编辑态下不要调用重排逻辑。

**验收点**：编辑第一轮的文字并「仅保存」→ 会话标题同步变化，且并排状态**没有**丢失。

### 2.8 重新生成

- 入口：卡片标题栏的「重新生成」，**仅最新一轮**、且该条不在生成中时才可用；
- 行为：把该条清空为「等待中」（清空 text / status / error / elapsedMs / droppedImages），
  推 `reset` 让界面重置该卡片，然后重新发起请求；
- 成功 / 失败 / 取消的收尾与 §2.3 一致。

### 2.9 历史会话

- 每次会话变更后**自动落盘**（含每轮展示设置、勾选模型、共享上下文）；
- 列表按 `updatedAt` **倒序**，每项显示标题、更新时间、轮数；
- 点开恢复：会话里存的勾选与每轮看法**都要恢复**；
- **删除**：两段式（先点成「确认」，3 秒内再点才真删）—— webview 里 `confirm` 不可靠；
- 删除的是**当前**会话 → 自动新建一个空白会话（保留当前勾选）；
- 「新建会话」保留当前勾选模型。

**边界情况**

- 会话文件损坏 / 已不存在 → 提示「这个会话已不存在或已损坏。」并刷新列表，不崩；
- 列表读取时跳过无法解析的文件。

### 2.10 导入到 Copilot

把对话导出成 Markdown 文件，方便在 Copilot Chat 里用 `#文件引用` 继续聊。

| 范围 | 内容 |
|---|---|
| **导入单条** | 该轮提问 + 该模型的这条回答（带 `## 第 N 轮` 标题） |
| **导入本组** | 该模型在本会话里的**全部**对话（不带轮次标题），轮次之间用 `---` 分隔 |

流程：

1. 生成文件名 `<安全化(会话标题)>-<安全化(模型名)>-<第N轮|完整对话>.md`；
   安全化 = 非 `[a-zA-Z0-9._-]` 一律替换为 `-`、裁到 60 字符、空则兜底 `model`；
2. 写入当前工作区根目录下的 **`.multi-model-context/`**（该目录已在 `.gitignore`）；
   没有打开工作区时改写到扩展自己的存储目录；
3. 打开该文件，并把 **`#相对路径`** 复制到剪贴板（`#` 才能在 Copilot 里被识别为文件引用）；
4. 提示用户去 Copilot Chat 粘贴。

**边界情况**：写文件失败 → **把完整内容复制到剪贴板**并给出警告
（无论怎样都不让用户白点一次）。

### 2.11 Markdown 渲染

**零依赖手写渲染器**（理由见 §8.6），渲染的是**模型返回的内容**，因此安全第一。

| 支持 | 不支持 |
|---|---|
| 标题、粗体、斜体、删除线、行内代码、围栏代码块（带语言标签角标） | 语法高亮 |
| 有序 / 无序列表（含嵌套）、表格、引用块、分隔线、链接 | 内嵌 HTML（一律转义） |
| 段落内换行转 `<br>` | 数学公式、脚注、任务列表等扩展语法 |

**安全要求（必须逐条满足）**

- 所有文本**先转义** `& < > " '` 再拼标签；
- 链接协议**白名单**：只放行 `http/https`、`mailto:`、`#`、`/`、`./`，
  `javascript:` 与 `data:` **一律拒绝**（拒绝时保持原文，不生成 `<a>`）；
- 行内代码先抽成**占位符**再处理强调符号，否则 `` `**x**` `` 里的 `*` 会被误当粗体；
- 代码块内不解析 Markdown（按 ``` 切分，奇数段原样转义）。

**性能**：超过 **20000 字符**的回答退化为纯文本渲染（不做 Markdown 解析），避免重排卡顿。

**流式渲染**：chunk 不逐个渲染，按 **90ms** 合并成一次。

### 2.12 提示与错误

- 顶部提示条三种级别（info / warn / error），**8 秒**后自动消失；
- 错误码中文化，至少覆盖：

  | 错误码 | 中文建议要点 |
  |---|---|
  | `NoPermissions` | 尚未授权该模型；去命令面板执行「管理语言模型访问」 |
  | `Blocked` | 被安全策略拦截；企业环境检查组织策略 |
  | `NotFound` | 模型不存在或无权访问 |
  | `Unknown` | 未知错误，可重试或检查端点配置 |

- 错误码可能是 `'NotFound'` 也可能是 `'LanguageModelError.NotFound'`，
  统一取**最后一段**去查表；
- **「用户取消」与「失败」必须区分**：取消显示「已取消」，不算错误、不显示错误码。

### 4.3 收窄与容错规则

**入方向**（`src/protocol.ts`）：把 `unknown` 收成有类型的消息。

- 非对象、缺 `type`、`type` 不认识 → **返回 undefined 直接忽略**（不抛错）；
- 字段类型不对 → 视为「未提供」，不要强转；
- **`send.selected` 缺省时必须保持 `undefined`**，不能归一化成 `[]` ——
  否则就从「沿用会话勾选」变成了「一个都没勾」；
- 图片数组里**没有 `dataUrl` 的项直接丢弃**；
- 各 handler 不再自己写 `?? []` / `typeof x === 'string'`，防御集中在解析层。

**出方向**：⚠️ **`postMessage` 会丢掉值为 `undefined` 的字段。**
所以 `prompt.contextSource` 用 **`null`** 表示「上下文已被清除」——
用 `undefined` 的话该字段根本不会传过去，前端就不知道该清除。

**面板已关闭时不要 `postMessage`**（会抛 "Webview is disposed"）：
自己维护一个 `disposed` 标志位，关闭后所有推送直接 return。

## 5. 数据模型与存储

### 5.1 类型定义（落盘结构）

```ts
/** 落盘保存的图片附件。真实二进制存在 images/ 下。 */
interface ImageAttachment {
	file: string;   // 文件名（不含目录）
	mime: string;   // 如 image/png
	name?: string;  // 仅用于界面提示
}

/** 发给 Webview 的图片（比落盘版多一个 dataUrl） */
interface WireImage extends ImageAttachment {
	dataUrl: string;
}

type ResponseStatus = 'pending' | 'streaming' | 'done' | 'error' | 'cancelled';

/** 单个模型对某一轮的应答 */
interface ModelResponse {
	text: string;
	status: ResponseStatus;
	error?: string;
	elapsedMs?: number;      // 从开始请求到结束的毫秒数
	droppedImages?: boolean; // 该模型不支持图片，本次已降级为纯文本
}

/** 某一轮独立的展示设置 —— 展示状态的唯一真相源 */
interface TurnView {
	focusKey?: string;       // 单读看谁
	compareKeys?: string[];  // 并排哪几个
}

/** 一轮对话 */
interface Turn {
	id: string;
	at: number;                        // 时间戳
	prompt: string;
	editedAt?: number;                 // 最后一次编辑提问的时间
	images: ImageAttachment[];
	view?: TurnView;
	responses: Record<string, ModelResponse>;  // key = 模型 key
}

/** 共享上下文来源 */
interface ContextSource {
	turnId: string;
	modelKey: string;
}

/** 一次完整会话 */
interface Session {
	id: string;
	title: string;              // 取自首条提问，仅用于列表展示
	createdAt: number;
	updatedAt: number;
	selectedModels: string[];   // 上次勾选的模型 key
	contextSource?: ContextSource;
	turns: Turn[];
}

/** 历史列表用的轻量摘要 */
interface SessionSummary {
	id: string;
	title: string;
	createdAt: number;
	updatedAt: number;
	turnCount: number;
}

/** 暴露给界面的模型信息 */
interface ModelRef {
	key: string;      // `vendor:id`
	id: string;
	vendor: string;
	family: string;
	name: string;
	maxInputTokens: number;
	supportsImages?: boolean;  // undefined = 无法判断（见 §2.6）
}
```

**发给 Webview 的会话 / 轮次**：`WireSession` / `WireTurn` = 把 `images` 换成带
`dataUrl` 的版本，其余字段原样。图片是否带得出来取决于文件是否还在（丢了就跳过这张）。

### 5.2 存储位置与布局

```
<VS Code globalStorage>/local.multi-model-compare/
├── sessions/<sessionId>.json   每个会话一个文件
├── images/<uuid>.<ext>         图片二进制，被会话文件按文件名引用
└── contexts/                   未打开工作区时，「导入到 Copilot」写这里
```

- **原子写入**：先写 `<target>.tmp` 再 `rename`，避免中途崩溃留下半截 JSON；
- 会话文件名取 `basename(id)`（**防目录穿越**）；图片文件名同理；
- 启动时**清理孤儿图片**（没有被任何会话引用的）—— 清理失败不影响主流程；
- 图片扩展名按 MIME 映射：`png / jpg(jpeg) / gif / webp / bmp`，未知用 `bin`；
- 读取时跳过损坏 / 无法解析的文件，不让一个坏文件搞挂列表。

### 5.3 落盘时机

- 提问：建轮次后立即落盘（此时各模型还是 `pending`），全部结束后再落盘一次；
- 每个会改变会话内容的操作（勾选、展示设置、共享上下文、编辑提问、删除）都要落盘；
- 落盘同时更新 `updatedAt`（历史列表按它排序）。

### 5.4 设置项（3 个）

| 设置 | 类型 | 默认 | 作用 |
|---|---|---|---|
| `multiModelCompare.preferredVendors` | `string[]` | `["customendpoint"]` | 「我自己添加的模型」的来源白名单；空数组 = 不按来源过滤 |
| `multiModelCompare.onlyPreferredVendors` | `boolean` | `true` | 是否只显示白名单内的模型 |
| `multiModelCompare.maxSelectedModels` | `number` | `8` | 默认勾选上限；`0` = 不限制 |

- 三个设置变更都要**监听并立即刷新**（`onDidChangeConfiguration`），不需要重开面板；
- vendor 比较**统一转小写**并过滤空白项（否则大小写差异会让过滤落空）。

### 6.3 两套编译目标（`tsc -b`）

根 `tsconfig.json` 是**解决方案配置**（`files: []` + `references`），本身不编译任何东西。

|---|---|---|---|
| `tsconfig.ext.json` | `src/` | `out/` | Node / CommonJS |
| `tsconfig.webview.json` | `webview/` + `src/types.ts` | `media/dist/` | 浏览器 / **原生 ESM** |

Webview 侧的关键设置（**少一个就会出问题**）：

- `module` / `moduleResolution` 都用 **`NodeNext`**，配合 `webview/package.json` 里的
  `{"type":"module"}` —— 这样 tsc 会**强制** import 路径必须带 `.js` 后缀。
  浏览器不认隐式后缀，这是 ESM 最容易踩的坑；
- `"types": []` —— **排除 `@types/node`**。这段代码跑在浏览器里，
  引入 node 类型会让 `setTimeout` 返回 `NodeJS.Timeout` 而不是 `number`；
- `rootDir: "."` + `include: ["webview", "src/types.ts"]` ——
  产物路径才能是 `media/dist/webview/*.js`。

两个子项目都开 `composite: true`（`tsc -b` 要求），因此会强制产出 `.d.ts`；
把它们输出到 `.build/`（已 gitignore），保持 `out/` 与 `media/dist/` 干净。

**`media/dist/` 是产物，必须 gitignore。** 打包脚本整体复制 `media/`，所以产物会自动进包。

### 6.4 Webview 的资源与 CSP

HTML 由扩展侧生成（`src/webview/html.ts`），核心要求：

- 用 `webview.asWebviewUri()` 转换资源路径
  （`media/style.css`、`media/markdown.js`、`media/dist/webview/main.js`）；
- `localResourceRoots` 限定到扩展的 `media/` 目录；
- CSP：

  ```
  default-src 'none';
  img-src <cspSource> data: blob:;
  style-src <cspSource>;
  font-src <cspSource>;
  script-src 'nonce-<随机>' 'strict-dynamic'
  ```

- `script-src` 用 **nonce**；入口脚本用 `<script type="module" nonce=...>`；
- ⚠️ **不能**靠往 `script-src` 里加 `cspSource` 来解决模块加载 ——
  CSP3 规定 script-src 里一旦出现 nonce，host-source 就会被**忽略**；
- `'strict-dynamic'` 保留的理由：ESM 静态 import 实际会继承入口脚本的 nonce
  （实测过，带对照组），所以它不是「必须」；保留是为了把信任模型写显式，
  并顺带允许动态 `import()`。

**`media/markdown.js` 保持普通脚本，不要改成 ESM**：
Node 侧的冒烟测试用 `require()` 加载它（见 §10.1）。它是零依赖的独立文件，
通过 `window.MarkdownRenderer` 暴露给前端。

### 6.5 打包与安装（脚本，零下载）

打包进 vsix 的文件走**白名单**：

```
package.json  out/  media/  README.md  LICENSE
```

- 因此源码、`docs/`、`scripts/` 本来就不会进包 —— **不需要 `.vscodeignore`**
  （曾经有一个，但它从未被任何脚本读取，已删除；重建时不要再加）；
- vsix 本质是一个特定结构的 zip：
  `[Content_Types].xml` + `extension.vsixmanifest` + `extension/`；
- 安装脚本把同样的白名单复制到 `~/.vscode/extensions/<publisher>.<name>-<version>/`，
  并先清掉同前缀的旧版本目录；
- ⚠️ 打包 / 安装脚本里的白名单是**硬编码**的，新增运行期目录要**同步改两处**。


### 7.2 依赖方向（不可成环）

```
main → messages → turn → card / tab / strip / sessions → composer → display → ui / state / host
```

- `display.ts` 是**叶子**，只依赖 `state` / `ui` / `host` ——
  它被 `strip.ts` 与 `turn.ts` 调用，所以不能再反向依赖它们；
- `composer.ts` 里同时放「编辑提问」，因为提交编辑要调 `setSending()`，
  而 `setSending(true)` 又要取消编辑 —— 互相调用，放一个模块里最省事；
- `host.ts` 是**唯一**调用 `acquireVsCodeApi()` 的地方
  （⚠️ 它每个 Webview **只能调用一次**，重复调用会抛错）。

### 7.3 可测性约定：纯逻辑与「管道」分离

**新增逻辑请沿用这个分法。**

| 类型 | 例子 | 要求 |
|---|---|---|
| **纯逻辑（策略）** | `planContext()` / `filterModels()` / `reconcileSelection()` / `planImport()` / `parseWebviewMessage()` | 只做决策，**只用 `import type` 引入 vscode**，编译后不产生 `require('vscode')`，因此能直接在 Node 里单测 |
| **管道** | 构造 `LanguageModelChatMessage`、解码图片字节、读写文件、发请求 | 集中在 `request.ts` / `store.ts` / `importWriter.ts` 等少数文件 |

这条约定的价值：项目里最容易改错、又最不容易被发现的东西
（上下文回放规则、勾选收敛、协议收窄），恰好都是纯逻辑，
因此能拿到 **122 项断言**的保护（见 §10.1）。

## 8. 关键设计决策与理由

**只写「是什么」的话，重建时会用「更自然」但错误的方式实现。以下每条都踩过坑。**

### 8.1 为什么每个模型独立维护上下文

见 §1.4。补充：这决定了 `responses` 必须是 `Record<modelKey, ModelResponse>`
而不是「一个回答数组」—— 每个模型在同一轮里都有自己的状态与内容。

### 8.2 为什么展示状态按轮存，且**只能存一份**

**踩过的坑**：早期同时存在一份**全局**的 `compare` / `focusKey`（给悬浮条用）
和每轮 `view`（给渲染用）。两份状态各被读一半，结果是：

- 勾悬浮条复选框**只打钩，不进并排布局**；
- 点悬浮条卡片正文**只移动高亮，不切换显示的模型**。

症状是「点了没反应」—— 不报错、不崩溃，最难查。

**规则**：展示状态**只有一个真相源** ＝ 每轮的 `view`。
悬浮条不另存状态，它读写的是**最新一轮**的 `view`。

**推论**：任何「派生 UI」都要在**一处**统一刷新（见 §2.4 的同步清单），
漏一项就会出现「要点两下才有反应」。

### 8.3 为什么把「怎么看」与「问谁」分成两套控件

| 控件 | 影响 |
|---|---|
| 右侧开关 | 只决定**新问题发给谁**（关掉后已有的回答**仍然能看**） |
| 左侧复选框 | 只决定**怎么看**（并排对比） |

这两个维度独立，是因为用户经常需要「我不再问它了，但我想回头对比它之前答的」。
合并成一个开关会导致：关掉就看不到历史回答（或反过来，勾了就一定被提问）。

**重建时不要为了「简化」把它们合并。**

### 8.4 为什么只允许编辑最新一轮

历史轮次一旦被改写，后续轮次会回放「**新提问 + 旧回答**」，上下文自相矛盾。
与其提供一个会产生错误上下文的功能，不如不支持。同理，编辑**只改文字**：图片原样保留。

### 8.5 为什么图片能力要「两段式降级」

`vscode.lm` 消费侧没有稳定的能力查询接口（见 §2.6）。两条路：

- 全部带图试一次 → 明确不支持图片的模型每次都白失败一次（浪费请求与时间）；
- 全部先去掉图片 → 支持图片的模型永远收不到图。

所以按探测结果分三种情况处理。**代价**：能力未知的模型最多多一次失败请求。
这个代价是有意接受的。

### 8.6 为什么手写 Markdown 渲染器，不用成熟库

- 引入 `markdown-it` 等库会**打破零构建约定**（需要打包步骤，并牵动安装脚本）；
- 不做语法高亮（需额外库且体积大）—— 留白给 VS Code 自己的编辑器看更合适；
- 手写版本**可单独测试**（Node 里 `require` 直接跑），有 70 项断言覆盖它。

安全上必须「先转义再拼标签」+ 链接协议白名单（§2.11）。

### 8.7 为什么前端编译成**原生 ESM** 而不用打包器

- 零打包器是硬约束（§6.2）；
- 原生 ESM 让浏览器直接加载模块，`media/dist/` 里的文件与源码**一一对应**，
  调试时栈里看到的就是真实模块名；
- 代价：必须处理 import 的 `.js` 后缀（用 `NodeNext` 让编译器强制，§6.3）
  与 CSP（§6.4）。

### 8.8 为什么不用 `.vscodeignore`

打包走**白名单**（§6.5），不是「黑名单排除」。`.vscodeignore` 是 vsce 的机制，
本项目不用 vsce，因此它**从未生效** —— 留着只会误导人
（曾经的 README 就写着「打包 vsix 时排除的文件」，而实际打包根本没读它）。

### 8.9 为什么本扩展**完全不碰密钥**

不使用 `SecretStorage`，也没有任何 `context.secrets` 调用 ——
**密钥根本不经过本扩展**。鉴权与端点配置全由 VS Code 负责，
本扩展只调用 `vscode.lm` 这个已鉴权的接口。

**重建时不要为了「安全」去加 SecretStorage 代码**：那会引入一个并不存在的数据流。

## 9. 非功能需求

### 9.1 容错

- 单个模型失败 / 超时 / 取消，**不影响**其它模型的显示与结果；
- 图片文件丢失 → 跳过该图，不让整个请求失败；
- 会话文件损坏 → 跳过并提示，不崩；
- 写导入文件失败 → 退回剪贴板，不让用户白点一次。

### 9.2 性能

| 措施 | 目的 |
|---|---|
| 流式 chunk 按 **90ms** 合并渲染 | 避免每个 chunk 都触发重排 |
| 超过 **20000 字符**退化为纯文本 | 避免 Markdown 解析 + 重排开销 |
| 图片 data URL **带缓存** | 同一张图不重复读盘 |
| 悬浮条只重建一次、状态变化只刷新对应迷你卡 | 避免流式期间整条重建 |
| 重排前后抓 / 还原**滚动锚点** | 切换聚焦时视口不跳 |
| 会话文件只存图片**文件名** | 避免文件膨胀 |

### 9.3 安全与隐私

- **不接触任何 API Key**（见 §8.9）；不使用 `SecretStorage`；
- **不解析** `chatLanguageModels.json`，只认 `vscode.lm` 报出的 vendor；
- 渲染模型返回内容时**先转义**，链接协议白名单（§2.11）；
- `openLink` 只放行 `http(s)://` 与 `mailto:`，防止被诱导打开本地文件或自定义协议；
- 文件路径一律过 `basename()`，防目录穿越；
- 会话与图片**只存本地**（VS Code `globalStorage`），不上传、不同步；
- 日志里不输出密钥。

## 10. 验收与验证

### 10.1 自动化

```bash
npm run compile   # tsc -b 必须无错（同时编扩展侧与前端）
npm test          # 122 项断言（pretest 会先编译）
```

| 套件 | 覆盖 |
|---|---|
| `scripts/smoke-render.mjs`（70 项） | Markdown 渲染：XSS（标题 / 列表 / 表格 / 引用 / 代码块 / 行内代码每个插入点）、语法正确性、边界（未闭合围栏、空串、单个特殊字符） |
| `scripts/unit-test.mjs`（52 项） | 上下文回放（含失败轮次不回放、丢过图不再发图、共享上下文追加条件）、模型筛选与勾选收敛、协议收窄（含 `send.selected` 缺省保留 `undefined`）、导入规划 |

⚠️ 单测只能加载 `out/` 下**无 vscode 运行时依赖**的模块 —— 所以先编译，
且新逻辑要按 §7.3 的约定写才能被测到。

### 10.2 前端手工回归

前端没有 DOM 测试环境（上 jsdom 会违反零依赖约定），靠 `scripts/preview.html`
手工回归。它用 mock 的 `acquireVsCodeApi` + 演示数据，
并使用与真实 Webview **一致**的 CSP。

> ⚠️ **必须用本地 HTTP 服务打开**（`python3 -m http.server`）——
> 前端是原生 ESM，`file://` 会被浏览器 CORS 拦掉。

### 10.3 端到端验收场景

改完代码后手工过一遍这 5 个场景：

1. **一问多答**：勾 3 个模型发问 → 三张卡片并发流式输出 → 显示各自耗时；
2. **并排对比**：勾悬浮条左侧复选框 → 真的进入并排（不只是打钩）→
   点某张卡片的名字 → 退出并排、单读它；
3. **上下文隔离**：让一个模型在某轮失败，下一轮提问 → 该模型的历史里**没有**别人的回答；
4. **编辑提问**：改最新一轮文字并「仅保存」→ 会话标题（若是首轮）跟着变、
   并排状态**没丢**、出现「已编辑」标记；
5. **图片降级**：给明确不支持图片的模型发图 → 卡片出现降级说明，
   且**没有**多余的失败请求。

### 10.4 纯 CSS 重构的验证手法

改样式但不想改观感时，**不要靠肉眼**：

```bash
git show HEAD:media/style.css > scripts/_old-style.css
sed 's|\.\./media/style\.css|_old-style.css|' scripts/preview.html > scripts/_cmp-old.html
python3 -m http.server 8000
```

然后用浏览器自动化在两个页面上**遍历 DOM**（`#app` 下每个元素），
对每个元素取一组 computed style（宽高 / 内外边距 / display / 颜色 / 字号 / flex / gap …）
做 diff。

⚠️ **单读与并排两种模式都要跑** —— 并排会触发大批 `.turn.tile` 下的覆盖规则。
这个手法揪出过一个「想当然」的改动（把并排时的 `.tabbar` 也隐藏了，
而原行为只隐藏 `.answers-label`）。

## 11. 明确不做（范围外）

以下在本版本中**有意不实现**。重建时不要自行添加，也不要为此改变架构。

- ❌ 编辑器代码上下文（选中代码作为输入）
- ❌ 工具调用（tool calling）
- ❌ 插件自行直连各厂商 HTTP API（统一走 `vscode.lm`）
- ❌ 模型参数调参界面（temperature 等）
- ❌ 多账号 / 多人协作 / 云同步
- ❌ 其它模型来源（如 Ollama）的特例处理 —— 只要它出现在 `vscode.lm` 里就能用
- ❌ 发布到 Marketplace（`private: true`，仅本地使用与 `.vsix` 分发）
- ❌ Markdown 语法高亮
- ❌ 并排对比的「自动高度对齐到最长」—— 各格等高、格内滚动
- ❌ 卡片宽度拖拽调整（v0.4.0 已移除，**不要「恢复」它**）
- ❌ 「显示结果」这类独立的显隐开关（v0.4.0 已移除；显隐由 §2.4 的展示方式决定）
